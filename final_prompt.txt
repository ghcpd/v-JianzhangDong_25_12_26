You are an experienced test engineer. Your task is to generate comprehensive tests for a Python project and execute them to verify functionality. Complete the following tasks in a single interaction:

**Role & Objective**
Act as an expert test engineer responsible for detecting untested modules, generating test files, creating automated test infrastructure, documenting the process, and executing the tests to ensure all components work correctly.

**Inputs & Context**
- The Python project structure contains:
  - Source code modules in a directory (e.g., `app/`, `src/`, or project root)
  - Existing test files in a `tests/` folder
  - You need to identify untested modules by comparing source modules against existing test files

**Step-by-Step Instructions**

1. **Detect Untested Modules**
   - Scan the source code directory to identify all Python modules
   - Scan the `tests/` directory to identify existing test files
   - Compare module names with test file names (test files follow pattern `test_<module_name>.py`)
   - Identify all modules that lack corresponding test files

2. **Generate Test Files for Untested Modules**
   - For each untested module:
     - Read and analyze the module's source code
     - Examine existing test files to understand the project's testing patterns and conventions
     - Generate a comprehensive test file named `test_<module_name>.py`
     - Include test cases covering:
       - All public functions and methods
       - Edge cases and boundary conditions
       - Error handling and exception paths
       - Valid inputs and expected outputs
     - Save each test file in the `tests/` folder with a unique name
     - Use pytest framework and follow project conventions

3. **Generate report.json**
   - Create a JSON file listing all untested modules detected
   - Use this exact structure:
   ```json
   {
     "problems": [
       {
         "id": "1",
         "module_name": "example_module_1",
         "file": "example_module_1.py",
         "test_file": "test_example_module_1.py"
       },
       {
         "id": "2",
         "module_name": "example_module_2",
         "file": "example_module_2.py",
         "test_file": "test_example_module_2.py"
       }
     ]
   }
   ```
   - Assign sequential numeric IDs starting from "1"
   - Include module_name, source file path, and corresponding test file name

4. **Generate auto_test.py**
   - Create an automated test execution script that:
     - Discovers all test files under the `tests/` folder using pytest
     - Executes all discovered tests
     - Calculates test coverage using `coverage.py`
     - **Coverage Configuration (Critical):**
       - ONLY measure coverage for the original source code directory (e.g., `app/`, `src/`, or project modules)
       - EXPLICITLY exclude the `tests/` directory from coverage measurement
       - Use appropriate coverage.py flags to target only source code
     - Writes the final coverage results to `logs/test_run.log`
     - Creates the `logs/` directory if it does not exist
     - Includes error handling and clear output formatting
     - Generates both console output and log file output

5. **Generate README.md**
   - Create comprehensive documentation that includes:
     - Overview of all generated files and their purpose
     - Description of each generated test file and what it tests
     - Clear instructions on how to run `auto_test.py`
     - Explanation of how to check coverage logs in `logs/test_run.log`
     - Project structure overview
     - Test execution workflow
     - Troubleshooting guidance
   - Use clear Markdown formatting with sections, code blocks, and lists

6. **Execute Tests**
   - Run the generated `auto_test.py` script
   - If tests fail, analyze the failures:
     - Read the actual source code implementation
     - Identify incorrect test assumptions
     - Fix the test files to match actual implementation behavior
     - Re-run tests until all pass
   - Verify that:
     - All tests execute successfully
     - Coverage reports are generated correctly
     - Log files are created with complete results
     - HTML coverage reports are available

**Output Specification**

Generate and save the following files:
1. **Test files** in `tests/` folder:
   - One file per untested module: `test_<module_name>.py`
   - Each file must contain comprehensive pytest test cases

2. **report.json** in project root:
   - Valid JSON format
   - Lists all untested modules with sequential IDs
   - Includes module_name, file, and test_file fields

3. **auto_test.py** in project root:
   - Executable Python script

   - Creates logs/ directory if missing

4. **README.md** in project root:
   - Complete documentation in Markdown format
   - Covers all generated files, usage instructions, and workflow
   - Includes troubleshooting section

5. **Test Execution Results**:
   - Execute auto_test.py and ensure all tests pass
   - Fix any test failures by correcting test assumptions
   - Verify logs/test_run.log contains complete coverage results
   - Confirm HTML coverage reports are generated
